# ADR-0004: Python and FastAPI for the backend

- Status: Accepted
- Date: 2026-09-23
- Deciders: engineering

## Context

The differentiating work in neVus is image analysis: fiducial detection with pose, coin fitting, segmentation, Feret measurements, feature-based alignment, later small learned models. The deployment target is a low-power x86 home server without a discrete GPU, packaged as one container. The team is one engineer; operational simplicity is a stated principle. Alternatives considered: Go (as in the maintainer's previous project) with OpenCV bindings and ONNX through cgo; Node/TypeScript with `sharp` and `onnxruntime-node`; Python with OpenCV, NumPy and ONNX Runtime.

## Decision

The backend is Python 3.13 with FastAPI and Pydantic v2, SQLAlchemy 2.0 with Alembic, `opencv-python-headless`, NumPy, ONNX Runtime (CPU), Pillow with HEIF support, and WeasyPrint for PDF. Dependencies are managed with `uv` and locked. Training and model export live in a separate `ml/` project so PyTorch never enters the runtime image. Python 3.13 rather than 3.14 keeps the optional OpenVINO execution provider (x86_64, CPython 3.11–3.13 wheels) available for an accelerated image variant.

## Consequences

- The whole analysis toolchain has prebuilt wheels for linux/amd64 and linux/arm64, so multi-architecture images need no native builds.
- The container is Debian-slim based (musl has no manylinux wheels) and larger than a static-binary image, roughly 450–550 MB; a size budget is asserted in CI.
- The GIL is not a bottleneck: NumPy, OpenCV and ONNX Runtime release it, and heavy work runs in separate processes anyway.
- The API contract is OpenAPI generated by FastAPI; the frontend client is generated from it and type-checked.
